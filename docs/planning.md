# Модуль «Планирование развития»

Перенос методики из книги «Планирование развития системы» в систему. MVP:
ввод руками, «умный» только генератор шифра. Раздел в меню — «Планирование
развития», адрес `/planning`.

## Уровни и сущности

Система → Направление → Блок (направление + часть) → ДК → задачи плана.

| Сущность | Таблица | Ключ уникальности |
|---|---|---|
| Система | `PlanSystem` | код (RKII) |
| Направление | `PlanDirection` | система + код |
| Часть направления (= блок) | `PlanDirectionPart` | направление + код |
| Подсистема | `PlanSubsystem` | система + код |
| МС | `PlanModule` | система + номер |
| Этап | `PlanStage` | код |
| ДК | `PlanDk` | часть + номер |
| Задача плана | `PlanTask` | шифр |

Блок отдельной таблицы не имеет: это часть направления. Статусы ДК, приоритеты
направлений и уровни этапов — в `src/lib/domain.ts`.

## Шифр

`СИСТЕМА.НАПРАВЛЕНИЕ.ЧАСТЬ.ПОДСИСТЕМА.ДК.МС.ЭТАП`, неизвестные позиции
опускаются, номер повтора дописывается к этапу только у повторов (Р, Р2, Р3).
Собирает его только `src/lib/planning/cipher.ts`:

- `CIPHER_SETTINGS.segments` — порядок сегментов;
- `CIPHER_SETTINGS.subsystemSource` — откуда брать подсистему: `"dk"`
  (утверждено) или `"ms"`. Готовый вариант «подсистема из МС после ДК» —
  `CIPHER_SETTINGS_SUBSYSTEM_FROM_MS` (RKII.Gaz.Rte.01.TA.08.Р).

Шифр хранится у задачи (уникальный индекс, поиск «содержит»). После смены
формата или кода в справочнике шифры пересобираются: при правке справочника
автоматически, после смены настройки — кнопкой «Пересобрать шифры» на
вкладке «Справочники».

Номер МС выдаёт счётчик `PlanSystem.lastMsNumber`: номер удалённого МС
повторно не выдаётся, номер МС не правится. Номер ДК — следующий в блоке.

## Сроки

Старт, длительность в неделях, финиш: достаточно двух, третье считается
(`src/lib/planning/dates.ts`). Финиш — последний день включительно, не раньше
старта. Календарь 2026–2027 (`PLAN_CALENDAR`), шкала диаграммы — недели ISO.

## Команды

```
npm run planning:sample                         # тестовый пример: Gaz · Rte · ДК 01 и 02, МС 08
npm run planning:import -- книга.xlsx           # пробный разбор книги, база не меняется
npm run planning:import -- книга.xlsx --apply   # запись справочников из книги
```

Импорт ищет таблицы на листах по подписям колонок (код, название, № МС,
подсистема, версия, уровень, цель, срок, приоритет, ОФТ…) и печатает, что
опознал. Записи находятся по коду (МС — по номеру), повторная загрузка
обновляет, а не дублирует.

## Миграция и откат

Миграция `20261013203439_planning_module` только добавляет восемь таблиц,
существующие не меняет. Откат:

```
npx prisma db execute --file prisma/migrations/20261013203439_planning_module/down.sql
```

Скрипт удаляет таблицы модуля и снимает отметку о применении миграции, поэтому
`npm run db:deploy` после отката накатит модуль заново.

Перед откатом остановите приложение и сделайте копию базы (`npm run backup`):
откат удаляет данные модуля.

## Чего в MVP нет

Модуль «Контроль» (узкие места, нагрузка, конфликты по МС), связь с Jira,
карточки и статусы задач плана, автоматические переходы статусов,
автогенерация наименований, корзина, отдельные роли доступа.
