# Экраны MVP: TaskTracker

Документ описывает интерфейс первой версии. Главный принцип: человек, который сегодня
ведёт проект в Excel, должен сесть за приложение и работать без обучения. Таблица —
основной экран, всё остальное надстраивается над ней.

## Принципы, из которых вырос интерфейс

1. **Таблица — не «ещё один вид», а дом.** Excel-пользователь мыслит строками и
   колонками. Доска, таймлайн и карточка — это режимы просмотра той же таблицы, а не
   отдельные сущности.
2. **Редактирование по месту.** Клик в ячейку — правка. Enter — вниз, Tab — вправо,
   Esc — отмена. Никаких «открыть карточку, нажать Редактировать, нажать Сохранить»
   ради смены статуса.
3. **Копипаст обязателен.** Ctrl+C / Ctrl+V между Excel и приложением работает в обе
   стороны, блоком ячеек. Это то, что чаще всего ломает переезд.
4. **Ничего не теряется молча.** Любая правка попадает в историю изменений задачи, кто
   и когда. В Excel этого не было, и именно это чаще всего называют причиной переезда.
5. **Колонки настраиваются.** Показать/скрыть, переставить, закрепить слева, задать
   ширину — и это состояние сохраняется для пользователя.

## Карта экранов

```
Список проектов ──> Рабочая область проекта ──> Карточка задачи (боковая панель)
                         ├── Таблица  (вид по умолчанию)
                         ├── Доска    (тот же набор задач, колонки = статусы)
                         └── Сроки    (таймлайн/Гант-лайт)
Мои задачи (сквозной экран по всем проектам)
Импорт из Excel (мастер, 4 шага)
```

## 1. Список проектов

**Задача экрана:** за 5 секунд понять, какие проекты идут, что горит, куда зайти.

**Содержание:** таблица проектов со столбцами: Проект, Статус, Руководитель, Заказчик,
Старт, Срок, Прогресс, Задач всего / просрочено. Сортировка по любому столбцу,
поиск по названию, фильтр по статусу и руководителю.

**Состояние:** статус — чип (Планируется / В работе / На паузе / Завершён / Отменён).
Просроченные задачи — красное число, это единственный красный элемент на экране,
чтобы он действительно читался.

**Действия:** «Новый проект», «Импорт из Excel» (кнопка живёт здесь же, потому что
первый сценарий нового пользователя — залить свою таблицу).

**Пустое состояние:** не пустой экран с надписью «нет данных», а два действия:
«Создать проект» и «Загрузить файл Excel» с подсказкой про поддерживаемые форматы.

## 2. Таблица задач — главный экран

**Задача экрана:** заменить тот самый лист «Задачи».

**Колонки по умолчанию** (в этом порядке — он повторяет типовую таблицу):
№, Задача, Ответственный, Статус, Приоритет, Начало, Срок, Готовность %, Трудозатраты,
Комментарий.

**Механика:**
- Закреплены слева: № и Задача. Остальное скроллится горизонтально.
- Строка-подзадача сдвинута отступом, сворачивается треугольником у родителя.
- Группировка одним селектором: без группировки / по этапу / по ответственному /
  по статусу. Заголовок группы показывает количество и суммарные трудозатраты.
- Фильтры в шапке каждой колонки + строка быстрых фильтров сверху:
  «Мои», «Просроченные», «На этой неделе», «Без ответственного».
- Последняя строка таблицы — всегда пустая, «строка ввода»: начал печатать название —
  создалась задача. Так это работает в таблице, так должно работать и здесь.
- Итоговая строка снизу: количество задач, сумма трудозатрат, средняя готовность.
- Экспорт в .xlsx одной кнопкой — с тем набором колонок и фильтров, который сейчас
  на экране. Это страховка: люди не переедут, если чувствуют, что заперты.

**Подсветка:** просроченный срок — красная дата, срок сегодня/завтра — янтарная,
завершённая задача — приглушённая строка с зачёркнутым названием. Никакой сплошной
заливки строк цветом: в Excel заливкой кодировали статус, здесь для этого есть чип.

**Массовые действия:** выделение строк чекбоксами, затем сменить статус / ответственного /
срок у всех разом, или удалить.

## 3. Доска

**Задача экрана:** тот же список задач, но колонками по статусу — для планёрок.

Колонки = статусы (Не начата, В работе, На проверке, Готово, Отменена).
Карточка на доске: название, ответственный (аватар), срок, приоритет, метка проекта
(если доска сквозная). Перетаскивание меняет статус и пишет запись в историю.

Сверху — те же фильтры, что и в таблице, и переключатель вида
«Таблица | Доска | Сроки». Фильтр не сбрасывается при переключении вида.

## 4. Карточка задачи

Открывается боковой панелью поверх таблицы (не отдельной страницей), чтобы не терять
контекст списка. Стрелками ↑/↓ — переход к соседней задаче списка.

**Блоки:**
- Название (редактируется по месту) и хлебные крошки «Проект / Этап».
- Свойства двумя колонками: Статус, Ответственный, Приоритет, Начало, Срок,
  Готовность, Трудозатраты план/факт, Метки.
- Описание — текст с простым форматированием и чек-листом.
- Подзадачи — компактный список с чекбоксами.
- Файлы и ссылки. Отдельно важно: ссылка на документ из старой таблицы
  (колонка «Ссылка») переносится сюда.
- Комментарии с упоминанием @коллеги.
- История изменений — свёрнута, разворачивается: «Иванов изменил Срок: 12.05 → 19.05».

## 5. Сроки (таймлайн)

**Задача экрана:** ответить на вопрос «успеваем ли», который в Excel решался
раскрашенными ячейками по дням.

Слева — дерево задач (этап → задача), справа — полосы по датам. Масштаб:
недели / месяцы / кварталы. Сегодняшний день — вертикальная линия. Просроченное —
красная полоса. Веха (задача без длительности) — ромб.

В MVP: перетаскивание полосы меняет даты; зависимостей между задачами нет —
это следующая итерация, и это надо честно сказать пользователю на экране.

## 6. Мои задачи

Сквозной по всем проектам список того, что назначено на меня, сгруппированный по
срокам: Просрочено / Сегодня / Эта неделя / Позже / Без срока. Это экран, который
человек открывает утром вместо того, чтобы обходить пять вкладок Excel.

## 7. Импорт из Excel

Мастер в четыре шага, описан отдельно: [../migration/excel-import.md](../migration/excel-import.md).
Живёт в двух местах: на пустом списке проектов и в меню проекта
(«Дозалить задачи из файла»).

## Что намеренно НЕ входит в MVP

Чтобы объём был честным, фиксирую границу:

- зависимости задач и критический путь;
- учёт времени с таймером;
- загрузка ресурсов и графики занятости;
- бюджеты и финансы;
- настраиваемые статусы и поля под каждый проект (в MVP набор фиксированный);
- уведомления на почту и в мессенджеры;
- мобильное приложение (веб адаптивен, но это не приложение);
- права доступа тоньше, чем «участник проекта / руководитель / наблюдатель».

## Поля, которые интерфейсу нужны от модели данных

Это запрос к аналитику и бэкенду, а не утверждённая схема.

**Проект:** id, название, код, заказчик, руководитель, статус, дата старта,
дата завершения (план), описание, архивность.

**Задача:** id, проект, родительская задача, порядковый номер, название, описание,
ответственный, статус, приоритет, дата начала, срок (план), дата факт. завершения,
готовность %, трудозатраты план, трудозатраты факт, метки, ссылка-источник,
кто создал, когда создана, кто изменил, когда изменена.

**Справочники:** пользователи, статусы, приоритеты, метки.

**История:** задача, поле, старое значение, новое значение, кто, когда.
