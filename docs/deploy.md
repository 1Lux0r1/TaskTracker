# Установка и работа системы

Инструкция для того, кто ставит систему, а не пишет код. Команды набираются в
окне терминала: на Windows это PowerShell (правая кнопка по меню «Пуск» →
«Терминал»), на macOS — «Терминал» из папки «Утилиты». Перед каждой командой
нужно оказаться в папке проекта: `cd путь\к\TaskTracker`.

Порядок такой: сначала посмотреть систему — это можно сделать прямо в браузере,
ничего не устанавливая, — потом поставить пилот на рабочий компьютер, потом,
когда понадобится, переехать в облако.

## Шаг 1. Посмотреть в браузере, ничего не устанавливая

GitHub умеет сам поднимать систему из репозитория: он выдаёт компьютер в
облаке, ставит туда всё нужное и открывает демо в соседней вкладке. На своём
компьютере устанавливать не надо ничего.

1. Откройте <https://github.com/1Lux0r1/TaskTracker>.
2. Зелёная кнопка **Code** → вкладка **Codespaces** → **Create codespace on
   main**. Если работа ещё не влита в `main`, сначала переключите ветку
   репозитория на `claude/project-thread-74ojym` и создавайте оттуда.
3. Откроется редактор в браузере. Внизу пойдут установка и сборка: первый раз
   это несколько минут, в следующие разы — секунды.
4. Когда система поднимется, GitHub сам откроет вкладку с ней. Если не открыл,
   загляните во вкладку **PORTS** внизу и нажмите на адрес напротив порта 3000.

Вход — `admin@demo.local` / `demo-2026`; чтобы посмотреть, что видит обычный
участник, — `user@demo.local` с тем же паролем.

Что полезно знать:

- Это отдельная база с выдуманными данными. Ломайте что угодно: начать заново —
  команда `npm run demo -- --fresh` в терминале редактора.
- Адрес виден только вам. Чтобы показать коллеге, во вкладке **PORTS** нажмите
  правой кнопкой по порту 3000 → **Port Visibility** → **Public**.
- Пока среда работает, GitHub считает её время. У личного аккаунта есть
  бесплатный месячный объём, дальше — платно, поэтому по окончании показа
  остановите среду: на <https://github.com/codespaces> кнопка **Stop**. Сама
  она засыпает через 30 минут простоя.
- Это витрина, а не рабочая система: среда временная, и данные в ней жить не
  должны. Для настоящей работы — шаги ниже.

### Постоянный адрес: витрина

У демо в Codespaces адрес временный, и среда засыпает. Если нужна ссылка,
которую можно просто дать посмотреть, есть витрина — заранее снятые страницы
живой системы, опубликованные на GitHub Pages:

<https://1lux0r1.github.io/TaskTracker/>

По экранам там можно ходить как в настоящей системе, с теми же
демонстрационными данными. Чего на витрине нет и быть не может: входа,
сохранения, фильтров и поиска. GitHub Pages отдаёт только готовые файлы,
сервера за ними нет, поэтому всё, что требует сервера, там не работает —
сверху каждой страницы об этом написано.

Как это устроено: в настройках репозитория **Settings** → **Pages** →
**Source** стоит **GitHub Actions**. Выкладывает витрину рабочий процесс
`.github/workflows/pages.yml`: он берёт папку `demo-site` и делает её корнем
сайта, поэтому короткий адрес открывает витрину сразу. Запускается он при
каждом изменении `demo-site` в `main` и вручную — вкладка **Actions**,
процесс «Витрина на Pages», кнопка **Run workflow**.

Второй режим, **Deploy from a branch**, тоже предусмотрен: тогда GitHub
выкладывает ветку целиком и страницы витрины оказываются по адресу
`.../TaskTracker/demo-site/`. На этот случай в корне репозитория лежит
`index.html`, который уводит на них, так что короткая ссылка работает в любом
режиме. Переключать режим туда-сюда не стоит: выкладка в этот момент идёт
двумя путями сразу, и какой из них победит, решает порядок завершения.

Пересобрать витрину после правок в интерфейсе (нужен установленный проект):

```
npm run demo            # в одном окне
npx playwright install chromium   # один раз
npm run demo:site       # в другом окне
```

## Шаг 2. Что нужно на своём компьютере

**Node.js версии 22 или новее.** Скачайте с <https://nodejs.org> вариант LTS и
установите, ничего в галочках не меняя. Проверить, что встал:

```
node --version
```

Ответ вида `v22.x.x` означает, что всё в порядке.

**Папка с системой.** Два способа, оба годятся:

- Без установки git: откройте <https://github.com/1Lux0r1/TaskTracker>, кнопка
  **Code** → **Download ZIP**, распакуйте архив. Внутри будет папка
  `TaskTracker-main` — переименуйте её в `TaskTracker` и положите, например, в
  корень диска: получится `C:\TaskTracker`.
- С git: `git clone https://github.com/1Lux0r1/TaskTracker.git`. Этот способ
  удобнее: обновление потом делается одной командой, а архив приходится
  скачивать заново и вручную переносить данные.

Дальше все команды набираются в этой папке. Перейти в неё:

```
cd C:\TaskTracker
```

Подсказка: в Проводнике можно открыть папку, нажать в адресной строке,
набрать `powershell` и нажать Enter — окно откроется сразу в нужном месте.

То же демо можно поднять и у себя, когда Node.js уже стоит:

```
npm install
npm run demo
```

Первый запуск дольше остальных: система собирается. Дальше откройте
<http://localhost:3000>, учётные записи те же. Остановить — Ctrl+C.

## Шаг 3. Поставить пилот

Одна команда из папки проекта.

**Windows:**

```
powershell -ExecutionPolicy Bypass -File scripts\install.ps1
```

**macOS:**

```
bash scripts/install.sh
```

Скрипт проверит Node.js (нужна версия 22 или новее, берётся с
<https://nodejs.org>), поставит зависимости, создаст настройки и базу, соберёт
приложение и спросит почту, ФИО и пароль первого администратора. Под ними вы и
войдёте; остальных заводите сами на странице «Сотрудники».

Запуск после установки:

```
npm run start:lan
```

Система открывается на <http://localhost:3000>.

## Шаг 4. Чтобы заходили коллеги

Команда `npm run start:lan` слушает не только сам компьютер, но и его адрес в
локальной сети — скрипт установки показывает этот адрес в конце работы. Коллеги
набирают `http://адрес:3000`.

Две вещи, о которых нужно знать:

1. **Брандмауэр Windows** при первом запуске спросит, разрешить ли сети доступ.
   Нужно разрешить для частной сети. Если окно не появилось, разрешение
   добавляется вручную: «Брандмауэр Защитника Windows» → «Разрешить работу
   программы» → Node.js.
2. **Вход идёт по обычному http, без шифрования.** Скрипт установки ставит для
   этого строку `SESSION_COOKIE_SECURE=false` в файле `.env`: иначе браузер
   отбрасывает cookie входа и войти нельзя. Плата за это — пароли идут по сети
   открыто. Для внутренней сети на время пилота это допустимо, для постоянной
   работы — нет: там нужен HTTPS, а его даёт облачный вариант из шага 7.

Компьютер, на котором стоит система, должен быть включён, пока с ней работают.

## Шаг 5. Автозапуск

Чтобы система поднималась сама после перезагрузки:

**Windows:** `powershell -ExecutionPolicy Bypass -File scripts\autostart.ps1`
**macOS:** `bash scripts/autostart.sh`

Скрипт заводит две задачи: запуск системы при входе в систему и резервную копию
каждый день в 3:00. Задачи заводятся на того пользователя, под которым вы их
создали, и система работает без окна консоли — закрыть его случайно нельзя.
Снять задачи — та же команда с `-Remove` (Windows) или `--remove` (macOS);
данные при этом не трогаются.

Остановить систему, не снимая автозапуск: Диспетчер задач → вкладка
«Подробности» → процесс `node.exe` → «Снять задачу».

## Шаг 6. Резервные копии

Копия снимается командой:

```
npm run backup
```

В копию попадают база и каталог вложений. База копируется средствами самой
SQLite, а не копированием файла: копия файла «на ходу» может оказаться
повреждённой, если в этот момент кто-то работал. После копирования скрипт
открывает копию и проверяет, что в ней есть таблицы.

Хранятся последние 14 копий, старые удаляются. Каждая копия — папка с датой и
временем, например `2026-09-24-0300`.

**Куда складывать.** По умолчанию — папка `backups` рядом с проектом. Это тот
же диск, что и сама система, поэтому при поломке диска пропадёт и копия.
Укажите в файле `.env` папку на облачном диске или внешнем носителе:

```
BACKUP_DIR=C:\Users\Вы\OneDrive\TaskTracker-backups
```

Посмотреть, какие копии есть: `npm run backup -- --list`.

**Восстановление.** Остановите систему (Ctrl+C) и выполните:

```
npm run backup -- --restore 2026-09-24-0300
npm run db:deploy
```

Прежние база и вложения не удаляются, а откладываются рядом с пометкой
`.before-restore-…`: если восстановились не из той копии, всё можно вернуть
переименованием. Удалите их, когда убедитесь, что данные на месте.

Раз в месяц стоит проверить, что копия действительно разворачивается: копия,
которую никто не восстанавливал, — это ещё не копия.

## Шаг 7. Переезд в облако

На сервере с Docker:

1. Скопируйте туда папку проекта.
2. Укажите домен: `echo "TASKTRACKER_DOMAIN=tracker.example.ru" > .env`
3. Поднимите: `docker compose up -d`

Caddy сам получит сертификат и включит HTTPS, поэтому строка
`SESSION_COOKIE_SECURE=false` в облаке не нужна и её быть не должно.

Данные живут в томах Docker, а не внутри образа, поэтому обновление
(`docker compose build && docker compose up -d`) их не трогает. Миграции
применяются при старте сами.

**Перенос данных с пилота.** Снимите копию на компьютере (`npm run backup`),
скопируйте папку копии на сервер и разложите её содержимое в том `data`:
`database.db` под именем `tasktracker.db`, папку `attachments` — рядом. После
этого перезапустите: `docker compose up -d`.

Резервная копия в облаке снимается так же: `docker compose exec app npm run backup`,
копии лежат в томе `backups`.

## Обновление системы

Перед обновлением снимите копию: `npm run backup`.

**Если папка получена через git:**

```
git pull
npm ci
npm run db:deploy
npm run build
```

**Если папка распакована из архива**, `git pull` работать не будет. Скачайте
новый архив (**Code** → **Download ZIP**), распакуйте рядом и перенесите в
новую папку из старой четыре вещи:

- файл `.env` — в нём настройки;
- файл базы (по умолчанию `prisma/dev.db`) — в нём все данные;
- папку вложений (по умолчанию `var/attachments`);
- папку `backups`, если копии складываются туда же.

Затем в новой папке выполните `npm ci`, `npm run db:deploy` и `npm run build`.
Старую папку не удаляйте, пока не убедитесь, что всё на месте.

Затем запустите систему заново.

## Если что-то не работает

| Что видно | В чём дело |
| --- | --- |
| Страница входа говорит, что администратора нет | Не выполнена `npm run auth:admin` |
| Пароль верный, но вход не проходит | В `.env` нет `SESSION_COOKIE_SECURE=false`, а система открыта по http |
| Коллеги не открывают адрес | Брандмауэр не пропускает, либо компьютер выключен, либо запущено `npm start` вместо `npm run start:lan` |
| Русский поиск ничего не находит | Данные попали в базу мимо форм; выполните `npm run search:reindex` |
| Вложение не прикрепляется | Файл больше 20 МБ, либо несколько файлов разом дают больше 21 МБ |
| `npm ci` падает | Node.js старее 22-й версии |
| PowerShell ругается на кавычки в скрипте | Файл потерял BOM при копировании; возьмите его из репозитория заново |
| Установка написала «Не удалось: …» | Шаг не прошёл, установка остановлена; строки выше говорят, какой именно |
