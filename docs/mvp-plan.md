# Технический план MVP

Цель MVP: команда переносит один реальный проект из Excel и работает в
TaskTracker без возврата к таблице. Всё, что не нужно для этой цели, вынесено
за рамки MVP.

## Критерий готовности

MVP готов, когда выполняется всё перечисленное:

1. Существующий файл Excel с задачами загружается и превращается в проект с
   задачами, исполнителями, сроками и сохранёнными пользовательскими
   колонками.
2. Задачу можно создать, отредактировать прямо в таблице, назначить, поменять
   статус перетаскиванием на доске.
3. По проекту видны сроки и зависимости на диаграмме Ганта.
4. Видно, что изменилось: история по задаче и по проекту.
5. Проект выгружается в Excel одним нажатием (страховка, без которой команда
   психологически не отпустит таблицу).

## Этапы

### Этап 0. Каркас (фундамент)

- Монорепозиторий, Next.js, TypeScript strict, ESLint, Prettier.
- Docker Compose: приложение и Postgres.
- Prisma: схема из `prisma/schema.prisma`, первая миграция, сиды с
  демо-проектом.
- Auth.js: вход по email-ссылке, пространство создаётся при первом входе.
- Каркас проверки прав: одна функция `can(userId, resource, action)`.

Результат: пустое приложение, в которое можно войти и увидеть своё
пространство.

### Этап 1. Задачи и проекты — ядро

- CRUD проектов и задач через tRPC.
- Настраиваемые статусы проекта, набор по умолчанию при создании.
- Подзадачи, приоритеты, метки, исполнители.
- Списочное представление: фильтры, сортировка, поиск, пагинация по курсору.
- Журнал изменений пишется на каждое изменение.

Результат: в системе можно вести задачи, но ещё неудобно.

### Этап 2. Табличное представление (главный аргумент для переезда)

- TanStack Table с виртуализацией, настраиваемый и запоминаемый набор колонок.
- Инлайн-редактирование ячеек, редактирование выделенного диапазона,
  копирование и вставка из буфера.
- Группировка по статусу, исполнителю, вехе.
- Пользовательские поля: определение, отображение, фильтрация.

Результат: человек из Excel садится и работает без обучения.

### Этап 3. Импорт и экспорт

- Загрузка `.xlsx` и `.csv`, определение заголовков, сопоставление колонок с
  полями системы вручную с сохранением сопоставления.
- Неопознанные колонки предлагается создать как пользовательские поля.
- Предпросмотр перед импортом и отчёт по ошибкам построчно.
- Импорт идёт фоновой задачей, прогресс виден в интерфейсе.
- Экспорт проекта в `.xlsx` с текущими колонками таблицы.

Результат: переезд занимает минуты, а не дни.

### Этап 4. Сроки, зависимости, Гант

- Зависимости с четырьмя типами связи и задержкой, запрет циклов.
- Вехи проекта.
- Диаграмма Ганта: полосы задач, связи, вехи, перетаскивание границ.
- Пересчёт расписания при сдвиге предшественника — предложение со списком
  затронутых задач, применяется по подтверждению.
- Подсветка просроченного и критического пути.

Результат: планирование, которого в Excel не было вообще.

### Этап 5. Доска, отчёты, уведомления

- Канбан-доска по статусам с перетаскиванием.
- Списание времени и отчёт «план против факта» по проекту и по человеку.
- Дашборд: что горит, что без исполнителя, что стоит.
- Email-уведомления: назначение, упоминание, приближение срока.

Результат: MVP закрыт, команда живёт в системе.

## Порядок работ и зависимости между этапами

Этап 0 идёт первым и блокирует всё. Дальше этап 1 блокирует 2, 3 и 4. Этапы 2
и 3 имеют смысл только вместе — если делать их порознь, миграция из Excel
получится, но работать в новой таблице будет неудобно, и команда вернётся в
Excel. Этап 4 можно вести параллельно с 2–3, он затрагивает другие экраны.
Этап 5 — последний, его части независимы друг от друга и могут выпускаться
поштучно.

## Что осталось за рамками MVP

- Realtime-совместное редактирование.
- Портфельное представление и зависимости между проектами.
- Планирование загрузки ресурсов с рабочими календарями.
- Автоматизации и правила вида «если статус стал X, то сделать Y».
- Мобильное приложение (мобильная вёрстка веба — да, приложение — нет).
- Публичный API и вебхуки.
- Интеграции с внешними трекерами.

## Открытые вопросы к аналитику

Ответы влияют на объём этапов 2–4, но не блокируют этапы 0–1:

1. Сколько человек и сколько проектов ведётся сейчас — от этого зависит, нужна
   ли многопространственность в MVP.
2. Как сейчас в Excel устроены статусы и какие колонки есть у каждой команды —
   это прямо задаёт набор статусов по умолчанию и список пользовательских
   полей.
3. Используются ли зависимости между задачами сейчас или сроки ставятся
   вручную — если вручную, этап 4 можно урезать до вех и Ганта только для
   чтения.
4. Нужен ли учёт времени в MVP или достаточно оценки без факта.
5. Требуется ли доступ для заказчиков извне — от этого зависит, нужна ли роль
   `VIEWER` с ограничением по проектам уже в MVP.
