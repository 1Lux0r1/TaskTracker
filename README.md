# TaskTracker

Система ведения проекта: переписка ЭДО, задачи по трекам, подписание
юридически значимых документов, график интеграций с контрагентами и отчётность
руководству. Заменяет набор рабочих таблиц Excel, которые команда ведёт рядом
с Jira.

## Где код

Основная кодовая база — ветка `claude/project-thread-74ojym`: работающее
приложение на Next.js. Эта ветка содержит только документацию предметной
области и проектные решения; исполняемой схемы здесь нет сознательно, чтобы не
было двух противоречащих моделей данных.

## Что стоит прочесть, даже если некогда

Три вещи из разбора файла, которые ломают обычные ожидания от трекера задач:

- **Колонка «Статус» в реестрах задач содержит хронику с датами, а не
  состояние.** Наивный импорт положит этот текст в поле статуса и уничтожит
  самую ценную часть файла.
- **Подписание документа — матрица независимых сторон**, а не линейный статус.
  При этом «Статус ДИТ» и «Статус подписания ДИТ» — разные колонки, и разбор
  обеих как сторон даёт дубль стороны.
- **В реестре «ДС к NDA» сторон по колонкам нет вообще**, а отказ записан только
  итоговой формулировкой. Вывод состояния из сторон там даст «черновик» при
  фактическом отказе.

## Отношение к Jira

Производственный трек остаётся в Jira: система хранит ключ задачи и подтягивает
её статус. Основание — слова заказчика; в самом файле колонка Jira заполнена в
одной записи из пятидесяти, то есть практики связывания пока нет. Экземпляр
Jira self-hosted, поэтому доступ для интеграции настраивается отдельно.

## Данные

Рабочие файлы заказчика в репозиторий не попадают: в них служебная переписка и
персональные данные. Документация описывает только структуру — без фамилий,
ссылок на ЭДО и содержания переписки. В `.gitignore` закрыты `*.xlsx`, `*.xls`,
`*.csv`.
