# TaskTracker

Веб-приложение для управления проектами со стороны заказчика: производственный
трек, переписка ЭДО, подписание юридически значимых документов, отчёты
руководству и аналитика. Существующие реестры загружаются из Excel как есть.

## Зачем

Заменить ведение проекта в Excel-таблицах, сохранив привычный вход и выход:
файл можно загрузить как есть, а данные в любой момент выгрузить обратно в .xlsx.
Модель построена на разборе реального рабочего файла: в нём оказалось восемь
разных реестров, а не один список задач.

| В Excel | В TaskTracker |
| --- | --- |
| Лист на проект | Проект с кодом, сроками и руководителем |
| Строка таблицы | Задача со статусом, приоритетом, сроком, исполнителем и треком |
| Реестр переписки отдельным листом | Письма ЭДО как своя сущность с поиском и сроками |
| Колонки «Статус подписания ДИТ / РСО / ДЖКХ» | Стороны подписания: у каждой свой статус, итог считается по ним |
| Колонка «Статус» с хроникой дат | Лента записей, где дата события отдельно от даты внесения |
| Текст «просрочка 49 дн.», устаревающий в тот же день | Просрочка считается при каждом открытии |
| Одна организация в четырёх написаниях | Справочник контрагентов с вариантами написания |
| Отчёт руководству собирается руками | Черновик собирается из данных и замораживается при отправке |
| Ручная подсветка просрочек | Просроченное считается и подсвечивается автоматически |
| Копия файла у каждого | Одна база, все видят актуальные данные |

## Возможности

- **Сводка** — открытые задачи, просрочки, сроки на ближайшую неделю, задачи без
  ответственного, карточки проектов.
- **Проекты** — код, название, описание, статус, сроки, руководитель; по проекту
  считаются готовность и часы (план / факт).
- **Задачи** — четыре трека (производственный, внутренний, внешний, юридический),
  статус, приоритет, внутренний и внешний ответственный, даты, оценка и факт в
  часах, процент готовности, подзадачи, письмо-основание, лента хроники.
- **Канбан-доска** — колонки по статусам, перенос кнопками (работает без
  JavaScript и на телефоне).
- **Переписка ЭДО** — входящие и исходящие письма, контрагент, срок исполнения,
  ссылка на карточку в ЭДО, реквизиты ответа, ключ задачи во внешнем трекере.
  Поиск по номеру, теме, контрагенту и комментариям; выборки «просроченные»,
  «срок в ближайшую неделю», «без ответственного», «без срока».
- **Юридические документы** — регламенты, ДС к NDA, контракты. Подписание
  описывается **матрицей сторон**: у каждой стороны свой статус, итоговый статус
  документа выводится из них, отказ любой стороны блокирует документ.
- **Отчёты руководству** — черновик за период собирается из фактических данных
  (закрытое за период, планы, просрочки, отказы в подписании), правится руками
  и замораживается при отправке.
- **Аналитика** — готовность, просрочки, срезы по статусам, трекам, исполнителям,
  направлениям переписки, контрагентам и статусам документов.
- **Календарь сроков** — месяц с задачами, письмами и документами; просроченное
  выделено.
- **Справочники** — сотрудники и контрагенты с вариантами написания.
- **Импорт из Excel** — три вида реестров: задачи, переписка ЭДО и реестры
  подписания. Лист выбирается вручную или определяется автоматически, шапка
  ищется в первых 10 строках, колонки распознаются по синонимам, строки итогов
  пропускаются. Колонка «Статус» с хроникой дат разбирается в ленту записей.
  Повторная загрузка обновляет записи, а не дублирует их.
- **Экспорт в Excel** — задачи, переписка, документы (двумя листами: документы и
  стороны подписания) и отчёт руководству, плюс файл-образец для импорта.

## Стек

| Слой | Решение | Почему |
| --- | --- | --- |
| Приложение | Next.js 16 (App Router), React 19, TypeScript | один проект на фронт и бэк, серверные экшены вместо отдельного API |
| Оформление | Tailwind CSS 4 | без отдельной библиотеки компонентов и лишних зависимостей |
| База данных | SQLite через Prisma 7 | запускается без внешнего сервера; переезд на Postgres — смена провайдера и адаптера |
| Excel | ExcelJS | чтение и запись .xlsx на сервере |
| Тесты | Vitest | разбор Excel покрыт юнит-тестами |

## Запуск

```bash
npm install
cp .env.example .env      # при необходимости поменяйте путь к базе
npm run db:deploy         # применить миграции
npm run db:seed           # демо-данные: 2 проекта, 7 задач, 4 сотрудника
npm run dev               # http://localhost:3000
```

## Структура

```
prisma/schema.prisma        модель данных
prisma/seed.ts              демонстрационные данные
src/app/                    страницы и серверные экшены
src/app/api/export/         выгрузка .xlsx
src/components/             формы, таблицы, канбан-доска, лента хроники
src/lib/db.ts               подключение к базе
src/lib/domain.ts           статусы, треки, вывод статуса документа по сторонам
src/lib/reports.ts          сборка черновика отчёта руководству
src/lib/search.ts           поисковая строка переписки
src/lib/validation.ts       проверка форм (zod)
src/lib/excel/columns.ts    колонки трёх видов реестров и их синонимы
src/lib/excel/chronicle.ts  разбор колонки «Статус», которая ведётся как журнал
src/lib/excel/import.ts     импорт задач, переписки и реестров подписания
src/lib/excel/export.ts     выгрузки
```

## Переход на PostgreSQL

1. В `prisma/schema.prisma` заменить `provider = "sqlite"` на `"postgresql"`.
2. `npm i @prisma/adapter-pg` и заменить адаптер в `src/lib/db.ts` на `PrismaPg`.
3. Указать строку подключения в `DATABASE_URL` и выполнить `npm run db:deploy`.

## Что не сделано

Приложение пока не разграничивает доступ: аутентификации и ролей нет, любой,
кто открыл адрес, видит и меняет всё. Для пилота в закрытом контуре это
допустимо, для внешнего доступа авторизацию нужно делать до запуска.

Также нет: интеграции с ЭДО и Jira (данные заводятся вручную или импортом),
вложений к задачам и документам, уведомлений о приближении сроков, диаграммы
Ганта и графика интеграций по контрагентам (сущность в модели есть, экрана нет).


## Разбор реального файла

Импорт проверен на рабочем файле заказчика — восемь листов, около сотни
содержательных строк (в реестре переписки больше тысячи строк с остатками
форматирования, реальных записей 50).
Что он даёт на нём сейчас:

| Лист | Распознаётся как | Результат |
| --- | --- | --- |
| Письма ЭДО | переписка | 50 строк → 41 письмо (дубли по номеру и направлению схлопнуты), 15 контрагентов |
| Внутренние задачи | задачи | 20 строк → 16 задач и 8 записей хроники с датами |
| Внешние задачи | задачи | распознаются, включая колонку внешнего ответственного |
| Задачи Производственные | задачи | распознаются |
| Регламенты инф. взаимодействия | реестр подписания | 9 документов, стороны ДИТ / РСО / ДЖКХ |
| ДС к NDA | реестр подписания | 9 документов, стороны «контрагент» и ДИТ, 2 отказа распознаны |
| РКИИЭ Отчёт АЮ | — | это форма отчёта, а не реестр: заводится в разделе «Отчёты» |
| График интеграций с РСО | — | матрица «контрагент × этап», в модели есть, экрана пока нет |

Сам файл в репозиторий не кладётся: в нём служебная переписка и персональные
данные, `.gitignore` закрывает `*.xlsx`.
